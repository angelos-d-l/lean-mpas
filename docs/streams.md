# streams.atmosphere and the clock

lean reads `streams.atmosphere` and keeps time as MPAS 8.4.2 does: the same parse, checks, defaults, packages, field
lists and log lines, the same clock, alarms and file names, and a step-by-step choice of the streams MPAS would read
and write. The code is four host units in `src/run/` (group `physics_support` of `config/units.json`):

| Unit | What it holds |
|---|---|
| `lean_clock.f90` | times and intervals on the bundled ESMF time manager, the clock, alarms, templates, file names |
| `lean_xml.f90` | MPAS's syntax check of the file, and the element tree for the ezxml subset that check lets through |
| `lean_stream_registry.f90` | generated by `tools/gen_stream_registry.py` from Registry.xml: 19 packages, 825 fields, 14 pools, the 8 immutable streams and their 707 entries |
| `lean_streams.f90` | packages, the stream inquiry, the parse, field lists, file names and the I/O plan |

The model uses these plans for its input reads, physics alarms and output writes. MPAS paths below are relative to
MPAS's `src/` (`reference/mpas_src/src/` after `./lean fetch-upstream`).

## What is read and written, and when

The streams are kept in MPAS's order: the 8 Registry streams (invariant, input, restart, iau, lbc_in,
ugwp_oro_data_in, ugwp_ngw_in, da_state), then the file's `<stream>` elements in file order. The three `plan_*`
routines reproduce `core_atmosphere/mpas_atm_core.F` and fill an `io_plan`.

- **At the start, `plan_start`** (`mpas_atm_core.F:118-151, 666-752`):
  - `read_invariant`: the `invariant` stream is read first when it is active and its input alarm rings (the file gave
    it `input_interval="initial_only"`).
  - `initial_stream`: `input`, or `restart` when `config_do_restart`. lean stops at the start when this stream would
    not be read (Departures, D10).
  - The input alarms of invariant, input and restart, both alarms of iau, and restart's output alarm are reset. In a
    restart run the output alarms of `output` and `diagnostics` are reset too, so no history or diagnostics file is
    written at the start of a restart run.
  - `write`: every active output stream whose output alarm rings. A recurring alarm always rings at the start (C7,
    below), so a cold start writes the first history and diagnostics files.
  - `diagnostics_rang` and `restart_rang` are false: MPAS looks at these two alarms only after a step (`:877-903`).
  - `lbc_read`: the first LBC read, when `config_apply_lbcs` and lbc_in's input alarm rings. That alarm is not reset
    here, so the first step also does an LBC update, as in MPAS.
- **Before each step, `plan_step_inputs`** (`:754-813`): `lbc_read` is the LBC update when lbc_in's alarm rings; the
  alarm is reset; then every input or input;output stream whose input alarm rings is noted and its alarm reset.
  `read` lists the ones to read: those for which `stream_active` is true, as `write` lists the streams to write.
  `read_logged` lists all of them: MPAS calls its read and logs `Read '<stream>' input stream valid at ...` even
  for a stream that reads nothing (ugwp_oro_data_in, ugwp_ngw_in and da_state at the first step of a default run).
  A consumer reads `read` and uses `read_logged` only for MPAS's log line.
- **After each step, `plan_step_outputs`** (`:826-909`), after the caller's `advance_run_clock`: `write` as at the
  start; `any_output` (any output alarm rang: MPAS computes the output diagnostics and logs its two timing lines);
  `diagnostics_rang` (MPAS resets the accumulated diagnostics); `restart_rang` (MPAS writes `restart_timestamp`);
  `rang_output` (the streams whose output alarm rang, whatever their packages: MPAS's note, as `read_logged`; the
  streams to write are in `write`). Every output alarm that rings is reset.

The resets are applied inside the `plan_*` call, before the caller's reads and writes. MPAS consults no alarm in
between, so the order is equivalent.

File names: `read_filename(set, i, when, ...)` and `write_filename(set, i, when, ...)` (C10, below). A stream without a
filename interval writes every record to the file named at its reference time, and one whose filename interval is
longer than its output interval writes several records to the file of the block, and the writer appends them.
`record_interval(set, clock, i, interval)` is MPAS's record interval of an input stream: the `record_interval`
attribute, else the recurring input alarm interval, else none.

Fields: `stream_fields(set, i, names)` gives the fields stream i reads or writes now, in the order MPAS added them
(none while `stream_active(set, i)` is false); `stream_has_field(set, i, name)` applies only the field's own rule
(F5, below).

## The clock (`framework/mpas_timekeeping.F` unless named)

- **C1. Time strings** (`:1143-1298`): `YYYY-MM-DD[_hh:mm:ss]`, split at `.` (fraction, at most 8 digits kept), `_`,
  `:` and `-`; numbers read list-directed; hours and days roll over (Feb 31 becomes Mar 3). Written as
  `YYYY-MM-DD_hh:mm:ss`, whole seconds. Errors: `Invalid DateTime string <s>`, `Invalid DateTime string (invalid time
  substring) <s>`, `Invalid DateTime string (invalid date substring) <s>`, `Invalid DateTime string<s>`.
- **C2. Interval strings** (`:1347-1591`): optional `D_`, `M-D_` or `Y-M-D_`, then `h:m:s`, `m:s` or `s`. Errors:
  `Invalid TimeInterval string <s>`, `Invalid TimeInterval string (invalid time substring) <s>`. Intervals with months
  or years work in alarms and file names; they have no seconds.
- **C3. dt** (`:1452-1474`): `'00:00:'` and dt written with `fW.9`, then C2; back to seconds with MPAS's formula and
  its `sd == 0` guard (`:1648-1653`).
- **C4. The clock** (`core_atmosphere/mpas_atm_core.F:299-363`): start from `config_start_time` (or the first token of
  the `config_restart_timestamp_name` file when it is `file`), step from `config_dt`, stop = start +
  `config_run_duration` unless that is `none`, else `config_stop_time`. Both given and inconsistent: WARN
  `config_run_duration and config_stop_time are inconsistent: using config_run_duration.` Neither: ERR `Neither
  config_run_duration nor config_stop_time were specified.`, then CRIT `Clock setup failed for core atmosphere`.
- **C5. Stepping** (`:280-302, 397-426`): stop when now >= stop; advance by the step.
- **C6. Alarms** (`:490-566, 814-985`): a recurring alarm with interval I rings while prev + I <= now; a reset sets
  prev = now - ((now - prev) mod I); a one-shot alarm rings while its time <= now and a reset unsets it; a reset acts
  only while the alarm rings.
- **C7. Anchoring** (`:992-1062`): prev = now - I - r with r from the reference time, so a recurring stream alarm
  always rings at the start.
- **C8. Stream alarms** (`framework/mpas_stream_manager.F:6198-6292`): `<stream>_input`, `<stream>_output`; `none`: no
  alarm; `final_only`: one-shot at the stop time, and the stream's reference time becomes the stop time;
  `initial_only`: one-shot at the start; else recurring from the start, anchored at the reference time.
- **C9. Templates** (`:2225-2324`): `$Y $M $D $h $m $s`, `$d` day of year, `$S` seconds of the day, `$B` gives `all`;
  a final `$` disappears; another letter is CRIT `ERROR: mpas_expand_string option $<c> is not a valid expansion
  character.` (`$G` among them).
- **C10. File names** (`framework/mpas_stream_manager.F:4136-4201, 3183-3191, 3686-3698`): with a filename interval
  the file time is the start of the block that holds `when`, counted from the reference time; without one a read
  expands at the read time and a write at the stream's reference time. The mesh file
  (`driver/mpas_subdriver.F:325-354`) expands at its reference time, or by the block rule at the start time.

## The parse (`framework/xml_stream_parser.c` unless named)

- **P1. Order** (`driver/mpas_subdriver.F:263-381`): `streams_inquire`, `packages_when`, the suite, `set_packages`,
  `clock_from_config`, `streams_mesh`, [the mesh read], `streams_parse`.
- **P2. Syntax check** (`:596-775`) with MPAS's texts behind `In file <f>, `.
- **P3. ezxml subset** (`external/ezxml/ezxml.c`): values in `"` or `'`, entities and character references, CR LF,
  whitespace in values becomes spaces, the first of repeated attributes wins, comments, `<?xml ?>` and `<!DOCTYPE>`
  skipped by the reader (the syntax check rejects them, as MPAS).
- **P4. Checks** (`:348-577`): name, type and filename_template required; the interval a type needs; the two WARNs
  for an interval of the other direction; the six filename_interval texts; template letters `YMDdhmsGSB`; no `<var>`
  or `<file>` in an `<immutable_stream>`; list files readable, even for an inactive stream; names unique; two streams
  share a template only if neither is an output stream. Tests on type, intervals, clobber_mode, io_type and
  precision are substring tests, first match wins. Names and templates are compared as C strings: trailing blanks
  count. The stream manager trims names, so `name="a"` and `name="a "` pass the check and are one stream there
  (`framework/mpas_stream_manager.F:353-357, 6038-6058`). As in MPAS, the second element's create fails without a
  line, but the error stands only when the element has no reference time, no record interval, a filename interval
  `none` and a type other than `none`: then CRIT `xml stream parser failed: <f>` alone. Otherwise its reference
  time, record interval, filename interval, alarms, packages and fields go to the first stream (its template,
  clobber mode, precision and I/O type do not). An alarm the first already has gives ERR `OOPS -- we have a
  duplicate alarmID<id>` and ERR `Requested <direction> alarm <id> already on stream <s>`, then the CRIT.
- **P5. Mesh stream** (`core_atmosphere/mpas_atm_core_interface.F:365-406`): `invariant` if its input_interval is
  exactly `initial_only`, else `restart` if `config_do_restart`, else `input`; looked up among `<immutable_stream>`
  elements only.
- **P6. Each stream**: `stream:NAME:ATTR` references resolved; the default filename interval (`:1137-1195, 1446-1504`);
  the log block; output directories made from the raw template; the create; the alarms; the packages; then, for a
  mutable stream, its `<file>` tokens, `<var>`, `<var_array>`, `<var_struct>` and nested `<stream>` elements, in that
  order whatever their order in the file.
- **P7. Alarm direction** (`framework/mpas_stream_manager.F:1188-1198`): an alarm for a direction the stream lacks is
  ERR `Attempting to add an alarm <id> to invalid direction for stream <s>`; an immutable stream keeps its Registry
  direction.
- **Nested `<stream>`** (`:1795-1848`, `framework/mpas_stream_manager.F:947-1064, 6145-6195`; as MPAS does, checked
  against an MPAS run with nested streams):
  - naming a Registry immutable stream: that stream's fields are added, with the nested element's packages (the
    packages the Registry attaches to them in their own stream are not carried over);
  - naming a mutable stream defined earlier in the file, or the stream itself: nothing is added, no line;
  - naming a mutable stream defined later: ERR `Stream <n> does not exist in call to
    MPAS_stream_mgr_get_property().`, then that stream's inline `var`, `var_array` and `var_struct` are added with the
    nested element's packages (its `<file>` lists and its own nested streams are not), and the run goes on;
  - naming no stream: the same ERR line, nothing added, the run goes on.

## Fields and packages

- **F1. Packages** (`core_atmosphere/Registry.xml:466-491`): `les` and `sfclayer` from their `active_when` on the
  values before suite resolution, with MPAS's log block; iau, limited_area, jedi_da, no_invariant_stream (off only
  when invariant's input_interval is exactly `initial_only`); after the suite, the scheme packages and their block
  (`core_atmosphere/physics/mpas_atmphys_packages.F:53-194`) and the three ugwp packages.
- **F2. Field packages** (`tools/registry/gen_inc.c:352-480, 2215-2509`): a field is active with no packages or one
  active package.
- **F3. Adding a field** (`framework/mpas_stream_manager.F:842-931`): unknown: ERR `Requested field <f> not available`,
  the parse fails; already there: WARN `Requested field <f> already in stream <s>`; then the packages string is
  scanned as `parse_package_list` does (`:4589-4664`: empty tokens skipped, the scan stops at the first active
  package, a last token of one character is never looked at), and an unknown name met gives WARN `One or more packages
  in '<p>' attached to field '<f>' is undefined`; an inactive field gives ` * Requested field <f> is deactivated due
  to packages, or is a scratch variable.` and is not added. A scratch field whose packages are active is added like
  any other field (a repeat gives the WARN); F5 leaves it out of the file. A pool: unknown: ERR `Requested pool <p> does not exist.`;
  else each member in the pool's order. A nested immutable stream: one WARN `One or more packages in '<p>' attached
  to fields from stream '<ref>' is undefined`.
- **F4. Immutable streams** (`tools/registry/gen_inc.c:2039-2205`): created before the parse, in Registry order, with
  the Registry's fields, each through F3. Their "deactivated" lines come before `Parsing run-time I/O configuration`.
- **F5. I/O activity** (`framework/mpas_stream_manager.F:4331-4333, 4538-4571`): a stream reads or writes only if its
  type is not `none` and it has no known package or one active; a field in it only if it has no attached packages or
  `parse_package_list` of them is true. A field whose attached packages are all unknown is never written. A scratch
  field (Registry `persistence="scratch"`) is never read or written, without a line: `MPAS_streamAddField` returns
  for a field that is not persistent (`framework/mpas_io_streams.F:504, 926`). So `<var_struct name="tend_physics"/>`
  gives the struct's persistent members only; `stream_fields` and `stream_has_field` leave scratch fields out.

## Departures (lean stops where MPAS crashes, aborts or runs on)

Each is an ERR line followed by the phase's CRIT (`Clock setup failed for core atmosphere`, `stream xml get attribute
failed: <f>` or `xml stream parser failed: <f>`), except D9 (a CRIT itself) and D12.

| # | Case (what MPAS does) | lean's text |
|---|---|---|
| D1 | a number list-directed input cannot read, or a month outside 1-12 (runtime error, ESMF abort, or a silent 1 January) | `Invalid DateTime string (unreadable number) <s>`, `Invalid DateTime string (month out of range) <s>`, `Invalid TimeInterval string (unreadable number) <s>` |
| D2 | an unusable reference_time, record_interval, filename interval or alarm interval of a stream (crash at first use) | the C1/C2/D1 line, then `In file <f>, stream "<s>": <attribute> "<value>" is not a valid time` (or `time interval`) |
| D3 | `config_dt` <= 0, or stop before start (endless loop) | `config_dt = <dt>: the time step must be positive`, `the stop time <t> is before the start time <t>` |
| D4 | `config_start_time = 'file'` with an unreadable file (runtime error) | `Cannot read the start time from file <name>: <iomsg>` |
| D5 | the tree reader fails after the syntax check passed (ezxml's partial tree); this includes a comment that holds `--`, e.g. `<!-- ---- hourly ---- -->`, after which MPAS silently drops every stream | `Problems encountered while parsing run-time I/O config file <f>` (MPAS's text), then the reader's detail |
| D6 | a closing tag with nothing open (segfault) | `In file <f>, Found unexpected closing tag "<n>" at line <l>.` |
| D7 | a `<stream>` named like a Registry immutable stream | `In file <f>, stream "<s>" is a Registry immutable stream; define it with <immutable_stream>.` |
| D8 | a nested `<stream>` inside `<immutable_stream>` (ignored) | MPAS's `In file <f>, the set of variables in stream "<s>" cannot be modified.` |
| D9 | `$G` in the template of a stream that has an alarm and is active (abort at first expansion) | MPAS's C9 CRIT, at setup |
| D10 | the initial stream (`input`, or `restart` with `config_do_restart`) is not read at the start: type none, no active package, no input alarm, or an alarm that does not ring at the start such as `final_only` (MPAS runs on without an initial state) | `In file <f>, stream "<s>" is not read at the start time: lean_mpas cannot read the initial state.` |
| D11 | no `<immutable_stream>` named as the mesh stream (CRIT alone) | `In file <f>, no <immutable_stream> named "<mesh>"; the mesh is read from it.` |
| D12 | C messages over 255 characters (cut), packages attributes over 255 characters (undefined) | not cut, kept whole |
| D13 | a C1, C2 or D1 failure of config_start_time, config_stop_time, config_run_duration or the restart_timestamp token (runs on with an undefined clock) | the C1/C2/D1 line, then CRIT `Clock setup failed for core atmosphere` |
| D14 | an attribute value without quotes, e.g. `type=output` (stream silently of type none) | D5's line, then `In file <f>, line <l>: the value of attribute "<a>" is not in quotes.` |
| D15 | a stream element without a name that the inquiry reaches (crash) | none at the inquiry, which skips it; P4's `stream must have the "name" attribute.` stops at the mesh step |

Not copied, and not stopped either:

- MPAS's stream manager looks stream names up as regular expressions (`framework/mpas_stream_list.F:226-298`). lean
  compares names as text, so a stream name with regular-expression characters (`.`, `*`, `[`) can behave differently.
- `stream:NAME:ATTR` is split at the last colon; C builds the attribute from the characters after every colon
  (`xml_stream_parser.c:949-967`). The two differ only for a NAME that holds a colon, in the text of the error line.

## The log lines

lean's lines, from ` Initializing MPAS_streamInfo from file streams.atmosphere` through ` ** Validating streams`, are
MPAS's, line for line: the packages blocks, `Reading streams configuration from file <f>`, `Found mesh stream with
filename template <t>`, the io_type line, ` ** Attempting to bootstrap MPAS framework using stream: <mesh>`, the
Registry's "deactivated" lines, `Parsing run-time I/O configuration from <f> ...`, one block per stream (` -----  found
[immutable ]stream "<s>" in <f>  -----`, filename template, filename interval, clobber mode, I/O type, direction,
reference time, record interval, real precision, `*** created directory <d> for stream "<s>"`, input alarm, output
alarm, package), the field lines of F3, and ` ----- done parsing run-time I/O from <f> -----`. Messages go through
`lean_messages` with MPAS's prefixes (`WARNING:`, `ERROR:`, `CRITICAL ERROR:`).

## Tests

```
python3 tests/streams/run.py                    # gfortran, strict flags; add --profile debug, --fc nvfortran
python3 tests/streams/run.py --only streams     # or clock, xml; --keep leaves build/streams/<fc>-<profile>/
python3 -m unittest tests.lean_cli.test_gen_stream_registry
```

The tests use MPAS's own code and runs:

- **Clock:** MPAS's `mpas_timekeeping.F` compiled unchanged, and `mpas_build_stream_filename` extracted verbatim, run
  the scenario files of `tests/streams/clock_cases/` beside `lean_clock`.
- **Parser:** MPAS's `xml_stream_parser.c` and `ezxml.c`, compiled unchanged with C stand-ins for the stream manager's
  callbacks (`tests/streams/oracle_stubs.c`), print MPAS's log lines and a trace of the calls for each
  `tests/streams/cases/<case>/`; lean prints the same. The cases MPAS cannot run (the departures) are pinned in
  `run.py`. So are the field lines, which the stand-ins do not print, for every case: a case without an entry must
  print none, and the two cases on the default stream lists take theirs from the `greece_60km` `strict_12h` run's log.
- **Real runs:** for every MPAS 8.4.2 reference run in `data/cases/*/reference/*/`: the stream setup window of the log
  line for line (`real_logs`), and the run loop step by step (`loop/...`: the steps, LBC updates, reads and output
  events of the log, the output file names of the run's directory, the record interval of lbc_in).
  The nested-stream, var_struct, list-file-package, duplicate and `final_only` cases are pinned in `run.py`
  (`REQUIRED_LINES` and the expected field lines); a real-run check of them needs an MPAS run with such a streams
  file, which is not in the release.

- **lean only:** `loop/lean_only_restart_run` compares lean's restart run with lean's own cold run, not with an MPAS
  log; only the initial stream (`restart`) and the absence of `output` and `diagnostics` writes at the start are
  pinned from MPAS's source. `loop/multi_record_names`, `loop/final_output` and `loop/lbc_offset` are pinned by hand
  too.

Tests that need `reference/mpas_src` or `data/cases` print SKIP without them. The parts that need MPAS's reference runs
(`data/cases/*/reference/`) skip unless you made those runs yourself.

The writer's field catalog is generated with `python3 tools/gen_field_catalog.py` from the same Registry parse as the
stream tables. `python3 tools/gen_field_catalog.py --check` checks drift without changing files. The generated header records
the SHA256 of the preprocessed Registry, including Noah-MP. It expands each var_array into its Registry constituents and
keeps MPAS's attribute order, including `descrition`, the misspelt attribute name MPAS's Registry gives to two MYNN
fields, kept as MPAS writes it; chvxy and chbxy use m/s ([fixes.md](fixes.md), Output).
